# C4C on AWS in one stack (CloudFormation)

Research use only. C4C returns regulatory text and citations; it is not legal advice.

This template installs the C4C regulatory MCP server in your own AWS account: one Fargate task in your private subnets, behind an internal load balancer that only your network can reach. It takes about 10 minutes. You type no secrets: the bearer token is generated by AWS Secrets Manager.

## Files

- `c4c-ecs-fargate.yaml`: the server (ECS on Fargate, internal load balancer, token, logs).
- `c4c-s3-mirror.yaml` (optional): a private S3 bucket and S3 gateway endpoint, so the server takes updates from your own bucket and never contacts C4C.

## Before you start

1. **Subscribe** to the free C4C listing in AWS Marketplace with the AWS account you will deploy in. Without the subscription, ECS cannot pull the image.
2. **Pick a VPC and two private subnets** in different Availability Zones.
3. **Check the subnets can reach AWS services.** On start, ECS pulls the image from Amazon ECR, reads the token from Secrets Manager and writes logs to CloudWatch Logs. The subnets need a NAT gateway, or VPC endpoints for `ecr.api`, `ecr.dkr`, `secretsmanager`, `logs` and an S3 gateway endpoint (ECR stores image layers in S3). The default image is in `us-east-1`; in another Region use the image URI shown on your Marketplace launch page, or keep a NAT gateway.
4. **Choose where updates come from:**
   - The C4C feed: get a free license key at `https://mcp-auth.claudeforcompliance.com/self-hosted`. The subnets need outbound HTTPS to `mcp.claudeforcompliance.com` (NAT or proxy).
   - Your own bucket: deploy `c4c-s3-mirror.yaml` first (see below). No license key on the server and no internet needed for updates.
5. **Know your client network,** the CIDR of the AI agents or users that will call C4C, for example `10.20.0.0/16`.
6. Optional: an ACM certificate (for HTTPS) and a Route 53 private hosted zone (for a name like `c4c.internal.example.com`).

## Install (console)

1. Open CloudFormation in the Region you want, choose **Create stack**, then **With new resources**.
2. Choose **Amazon S3 URL** and enter `https://c4c-marketplace-legal-046843662668.s3.amazonaws.com/c4c-ecs-fargate.yaml`.
   Or open the one-click link (us-east-1; change both `region` values for another Region): https://us-east-1.console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/create/review?templateURL=https://c4c-marketplace-legal-046843662668.s3.amazonaws.com/c4c-ecs-fargate.yaml&stackName=c4c
3. Name the stack, for example `c4c`.
4. Fill in the parameters:
   - **VPC**, **Private subnets** and **Client network** (required).
   - **Library update URL**: leave the default for the C4C feed and paste your **license key**, or enter your mirror URL and leave the key blank.
   - **CPU architecture**: `ARM64` (Graviton) costs about 20 percent less. The image supports both.
   - **ACM certificate ARN**: blank gives HTTP on port 80 inside your network; set it for HTTPS on 443. The certificate must cover the DNS name your clients use.
   - **Private hosted zone ID** and **DNS name**: optional friendly name.
   - Leave the rest at their defaults unless you have a reason.
5. On the last page, tick **I acknowledge that AWS CloudFormation might create IAM resources** and choose **Submit**.
6. Wait for `CREATE_COMPLETE` (about 5 to 10 minutes). The **Outputs** tab has everything you need next.

## Install (CLI)

```
aws cloudformation create-stack \
  --stack-name c4c \
  --template-url https://c4c-marketplace-legal-046843662668.s3.amazonaws.com/c4c-ecs-fargate.yaml \
  --capabilities CAPABILITY_IAM \
  --parameters \
    ParameterKey=VpcId,ParameterValue=vpc-0123456789abcdef0 \
    ParameterKey=SubnetIds,ParameterValue='subnet-aaaa1111\,subnet-bbbb2222' \
    ParameterKey=AllowedClientCidr,ParameterValue=10.20.0.0/16 \
    ParameterKey=LicenseKey,ParameterValue=<your free key>

aws cloudformation wait stack-create-complete --stack-name c4c
aws cloudformation describe-stacks --stack-name c4c --query "Stacks[0].Outputs"
```

For your own mirror, replace the `LicenseKey` line with `ParameterKey=UpdateUrl,ParameterValue=https://<bucket>.s3.<region>.amazonaws.com/c4c`. You can also run it from a local copy with `--template-body file://c4c-ecs-fargate.yaml`.

## What it creates

- An ECS cluster (unless you give an existing one) and a Fargate service running one task, in your private subnets, with no public IP.
- A task definition: the C4C image, read-only root filesystem, runs as UID 1000, all Linux capabilities dropped, no task role (the container gets no AWS credentials). `/data` and `/tmp` are task storage that is wiped when the task is replaced; the library re-downloads in about a minute.
- An internal Application Load Balancer. Its security group accepts only your client network, on 443 (with a certificate) or 80. The task accepts port 8080 only from the load balancer and sends out only HTTPS.
- A Secrets Manager secret with a generated 64-character token, and a second secret for the license key only if you entered one. Only the ECS execution role can read them.
- A CloudWatch Logs group (90-day retention by default).
- Optional: a Route 53 alias record in your private zone.

Nothing is created outside your account, and nothing is sent to C4C except, with the C4C feed, the license key on update downloads.

## Health checks and the first few minutes

`/healthz` returns 503 `no_library` until the first library is installed, normally within a minute, then 200. So:

- The load balancer marks the task unhealthy at first. That is expected.
- ECS ignores load balancer health for the grace period (10 minutes by default) so the task is not replaced while it downloads.
- If the library cannot be installed (wrong mirror URL, empty bucket, no license key, no outbound route), ECS replaces the task after the grace period and keeps trying. Check the log group for the reason.
- The container's own health check only confirms the process is answering, so a missing library does not cause restarts by itself.

## Get the token

Run the `GetTokenCommand` from the Outputs tab, for example:

```
aws secretsmanager get-secret-value --secret-id <AuthTokenSecretArn> --query SecretString --output text
```

Or open the secret in the Secrets Manager console and choose **Retrieve secret value**. Store it in your AI tool's secret store. To rotate it, change the secret value, then force a new deployment of the ECS service (`aws ecs update-service --cluster <ClusterName> --service <ServiceName> --force-new-deployment`); the running task keeps the old token until then.

## Check it and connect

From a machine in the allowed network:

```
curl <HealthUrl from Outputs>
```

Expect `{"ok":true,"library_version":"...","stale":false}`. Then point your AI tools at the `McpEndpoint` output with `Authorization: Bearer <token>`. Step-by-step setup for each AI tool is in [`../../CONNECT.md`](../../CONNECT.md).

## Optional: updates from your own S3 bucket

1. Deploy `c4c-s3-mirror.yaml` in the same Region as the server. Give it the VPC and the route table IDs of the private subnets. If those route tables already have an S3 gateway endpoint, set **Create a new S3 gateway endpoint?** to `false` and enter that endpoint's ID instead.
2. It creates a private, encrypted, versioned bucket with public access blocked. The bucket policy lets anyone read `c4c/*` only through that endpoint, and refuses non-TLS requests.
3. Fill the bucket from your gate job with the commands in `AWS-USAGE.md` (or the `SyncCommands` output). The gate needs its own IAM permission to write to the bucket.
4. Use the `UpdateUrl` output as **Library update URL** in the server stack and leave the license key blank.

The bucket is kept (not deleted) when you delete this stack, so you do not lose the mirror by accident.

## Update to a new version

Update the stack and change only **Container image URI** to the new tag (for example `...c4c-mcp:1.0.2`), keeping all other values:

```
aws cloudformation update-stack --stack-name c4c --use-previous-template --capabilities CAPABILITY_IAM \
  --parameters ParameterKey=ImageUri,ParameterValue=709825985650.dkr.ecr.us-east-1.amazonaws.com/cf-synergies/c4c-mcp:<new tag> \
    ParameterKey=VpcId,UsePreviousValue=true ParameterKey=SubnetIds,UsePreviousValue=true \
    ParameterKey=AllowedClientCidr,UsePreviousValue=true ParameterKey=LicenseKey,UsePreviousValue=true
```

(Add `UsePreviousValue=true` for any other parameter you changed from its default.) ECS starts the new task, waits for it to pass `/healthz`, then stops the old one, so there is no gap in service. If the new task never becomes healthy, ECS rolls back automatically. The library itself updates on its own; you do not need a stack update for new rules.

## Delete

```
aws cloudformation delete-stack --stack-name c4c
```

Or choose **Delete** on the stack in the console. This removes everything the stack created, including the token and license key secrets and the log group (export logs first if you need them). The mirror bucket from `c4c-s3-mirror.yaml` is retained; empty and delete it by hand if you no longer want it.

The S3 gateway endpoint is free; mirror storage is a few cents a month. C4C itself is free.

## Known limits

- One task. If its Availability Zone fails, ECS starts a new one in the other subnet; expect a few minutes of downtime while the library re-downloads.
- `AuditLog=file` writes to `/data/audit`, which is lost when the task is replaced. Use `stdout` to keep audit lines in CloudWatch Logs.
- HTTPS needs a certificate for the name clients use. The load balancer's own `*.elb.amazonaws.com` name will not match your certificate, so set a private DNS name when you use HTTPS.
